# MedAuth Permissioned Network — Deployment Guide

This describes how `medauth-pack-lifecycle` chaincode is deployed onto a
real **Hyperledger Fabric** permissioned network for the pilot, matching
the topology defined in the project's Scope of Work:

```
Organisations (peers)        Role
──────────────────────────── ─────────────────────────────
WissenPharmaMSP               Manufacturer — commissions packs
MediDistMSP                   Wholesaler — ship / receive
CityPharmacyMSP                Pharmacy — receive / dispense
RegulatorObserverMSP          Regulator — read-only observer (no write ACL)
WISSEN (Orderer org)          Governance / CA / ordering service
```

## 1. Prerequisites

- Docker + Docker Compose
- [`fabric-samples`](https://github.com/hyperledger/fabric-samples) checked out locally (provides `test-network` used for the pilot)
- Fabric binaries (`peer`, `configtxgen`, `cryptogen`) on `PATH` — installed via `fabric-samples/install-fabric.sh`

## 2. Bring up the pilot network

```bash
cd fabric-samples/test-network

# Bring up 3 organisation peers (manufacturer, wholesaler, pharmacy) +
# ordering service. The regulator is added as a 4th org via the
# addOrg3.sh pattern, renamed to RegulatorObserverMSP, with its MSP
# granted query-only chaincode endorsement policy.
./network.sh up createChannel -c medauth-channel -ca

# Add the regulator observer organisation (read-only)
./addOrg3.sh up -c medauth-channel -ca
```

> Rename `Org1/Org2/Org3` → `WissenPharmaMSP` / `MediDistMSP` /
> `CityPharmacyMSP` and the added org → `RegulatorObserverMSP` in
> `organizations/cryptogen/*.yaml` and `configtx.yaml` before bringing the
> network up, so identities match the MSP IDs referenced in the chaincode
> (`_assertNotRegulator`) and connection profiles.

## 3. Package and install the chaincode

```bash
cd ../../medauth-blockchain-drug-verification/chaincode/medauth-pack-lifecycle
npm install --omit=dev

cd ../../../fabric-samples/test-network
export PATH=${PWD}/../bin:$PATH
export FABRIC_CFG_PATH=${PWD}/../config

./network.sh deployCC \
  -c medauth-channel \
  -ccn medauth-pack-lifecycle \
  -ccp ../../medauth-blockchain-drug-verification/chaincode/medauth-pack-lifecycle \
  -ccl javascript
```

The endorsement policy should require signatures from at least the
manufacturer + one downstream org (e.g. `AND('WissenPharmaMSP.peer',
OR('MediDistMSP.peer','CityPharmacyMSP.peer'))`) so no single org can
unilaterally rewrite pack history — `RegulatorObserverMSP` is deliberately
excluded from the endorsement set since it only submits query (read)
transactions.

## 4. Point the API gateway at the network

Copy `connection-profile.example.json` to `connection-profile.json`,
fill in the real peer/orderer TLS endpoints and MSP paths generated by
`cryptogen`, then swap `backend/src/ledger/permissionedLedger.js` for a
thin adapter using the [Fabric Gateway SDK](https://hyperledger.github.io/fabric-gateway/)
that calls `CommissionPack` / `ShipPack` / `ReceivePack` / `DispensePack`
/ `RecallPack` / `QueryPack` / `GetEventTrail` instead of the local
SQLite-backed simulation. The validation rules are identical in both —
only the transport changes, so nothing in `backend/src/routes/*` needs
to change.

## 5. Smoke test

```bash
peer chaincode invoke -C medauth-channel -n medauth-pack-lifecycle \
  -c '{"function":"CommissionPack","Args":["9506000134352","LOT-2026-A1","SN-100001","2027-01-01T00:00:00.000Z"]}'

peer chaincode query -C medauth-channel -n medauth-pack-lifecycle \
  -c '{"function":"QueryPack","Args":["9506000134352","SN-100001"]}'
```

## Notes for the pilot

- **Zero PII on-chain** is enforced at the chaincode layer
  (`assertZeroPii` in `lib/packLifecycle.js`), not only at the API
  gateway — this is the ledger's own admission control, matching R3.
- **Key rotation** (R8): CA-issued enrolment certificates should be
  rotated on a ≤90-day cadence via `fabric-ca-client reenroll`; automate
  with a scheduled job hitting each org's CA.
- **KPI envelope** (R6): throughput/latency targets are validated at the
  API gateway (`/api/metrics/kpis`), not inside the chaincode — Fabric
  endorsement/ordering latency should be included in that measurement
  once wired to a real network.
